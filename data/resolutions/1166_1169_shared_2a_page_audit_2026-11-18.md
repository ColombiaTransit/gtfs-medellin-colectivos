Position-matched records are candidates for **one shared route** with multiple legal source references, not two GTFS services.

The system-level list of participants includes Palenque Robledal, Cootransblan, Transportes Medellín Castilla, Rápido San Cristóbal, and Conducciones América. **The resolution's named operator is not the route operator for every fiche.** Determine the actual operator from the row `EMPRESA PRESTA SERVICIO` on each fiche, before assigning agency_id and frequencies.

## Extraction defects found

1. The index reported **38 pages for 1166 but 37 for 1169**. The missing 1169 candidate is **PDF page 19 / Gaceta printed page 196**, route `250M AL6`. Visual inspection proves that its original page DOES contain both `HORARIO DE SERVICIO` and the `INTERVALO DE DESPACHO` table. It is a text-layer / detection false negative, **not a missing route**.
2. On 1166 PDF p9, the text-layer reads one Sunday interval as `12` while both printed original p9 tables show **17** for Sunday DÍA; this is an OCR/text-layer artifact.
3. Source route-code strings are noisy (examples `2SOMAL5`, `2534L9`, `2SSiD`). Never treat raw extracted code candidates as canonical identifiers.
4. Both original documents visibly repeat shared-system fiches. Overlapping values may be used as cross-source QA evidence, **never summed**.

## Completed visual timetable verification (18 November 2026)

The initial two-row sample above has now been **extended to all 38 shared fiche positions**. The authoritative result is [`1166_1169_shared_2a_2015_interval_visual_verified.csv`](1166_1169_shared_2a_2015_interval_visual_verified.csv), containing **38 historical fiche records** and the printed service start/end plus the eight printed `INTERVALO DE DESPACHO` minute cells for weekday, Saturday, Sunday, and holiday. Both original scans were independently placed side by side for every matched PDF page; the captured official table was read from its image, not silently accepted from PDF text extraction. Only one record per matching pair is stored to prevent duplicate GTFS services. The 75 earlier detections and 38 page pairs are not independent route counts.

The 38 positions cover two trunk, 14 feeder, ten direct and 12 integrated fiches from the shared system 2A source. The interval transcription is **historically verified for 2015 only**; route-code labels and names remain source-normalization candidates until heading-versus-code discrepancies, assigned operator, direction, and modern ArcGIS match are audited. Do not set `current_legal_validity=yes`, derive peak clock windows, or feed these records into a GTFS generator.

**Critical source/QA notes:**

- **246 AL2 / Blanquizal (PDF p. 11)**: the subsection heading prints `246 AL 2` but its fiche caption appears to print `245 AL 2`; the code field is OCR-distorted. Canonical modern route-code matching must retain this conflict instead of choosing either silently. The register uses the subsection code as a *candidate*.
- **250A AL5 / Curazao (PDF p. 17)**: the subsection heading says `250A AL 5`. The text-recognition code-field candidate looks like `250MAL5`; the visual register follows the source subsection, not the erroneous recognition.
- **255P / San Sebastián de Palmitas (p. 48)**: source prints weekday and Saturday **49 min DÍA / 60 min HMD**, and Sunday/holiday **99 min DÍA / 60 min HMD**. HMD is thus *longer* than ordinary DÍA on weekdays. Preserve these as printed historic figures; never auto-interpret HMD as a more frequent peak.
- **254 AL10 / 255 AL11 (pp. 27, 29)** print **52/30** weekday and **104/60** Sunday minute intervals; **255iD (p. 82)** prints **53/30** and **106/60**. These large intervals are not missing rows or zeros.
- **PDF p. 19 in 1169** was a page-index false-negative, not a missing source fiche. Side-by-side visual reading confirms identical `250M AL6` 9/6, 9/6, 17/12, 17/12 interval values in the two official originals.
- **Some code cells and heading labels differ** due to genuine scan/OCR noise. The cross-index CSV from the earlier pass remains a candidate source, not authoritative code normalization. Use this new visually transcribed table for *time figures* instead.
